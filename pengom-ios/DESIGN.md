# 펭곰이 iOS 설계

**기준: 쇼츠 앱을 본 시간(분).** 안드로이드판과 같은 기준, 같은 화면(`scroll-melt/index.html`), 같은 펭곰이를 쓴다.

넘긴 횟수는 쓰지 않는다. 보기 싫어서 휙 넘긴 것도 한 번으로 세기 때문에 "얼마나 봤나"의 답이 될 수 없고, iOS에서는 애초에 셀 수도 없다. 시간은 두 플랫폼 모두에서 정확하게 잴 수 있다.

## 1. 두 플랫폼 비교

| | 안드로이드 | iOS |
|---|---|---|
| 시간 재기 | 사용 정보 접근(앱 전환 기록)으로 1초 단위 | 스크린타임 DeviceActivity: 정해둔 분에 도달하면 알려줌 |
| 대상 앱 고르기 | 패키지 이름 고정 (인스타, 유튜브, 틱톡) | 사용자가 애플 선택 창에서 직접 고름 (앱 이름은 우리도 볼 수 없음) |
| 중간 한마디 | 화면 위 오버레이 | **알림 배너** (펭곰이 얼굴 + 한 줄) |
| 약속 초과 | 아래에서 올라오는 시트, "나간다"는 홈 화면으로 | **애플 공식 차단 화면**을 펭곰이로 꾸밈 (앱 화면을 실제로 가림) |
| 앱 화면 | WebView + `PengomNative` | WKWebView + 같은 이름의 브리지 |

## 2. 쓰는 애플 기능 (전부 무료, 사용량 과금 없음)

| 기능 | 용도 |
|---|---|
| FamilyControls | 스크린타임 접근 권한 (본인 기기용 `.individual`, iOS 16+) |
| FamilyActivityPicker | 사용자가 인스타·유튜브 등을 고르는 애플 기본 선택 창 |
| DeviceActivity | 하루 단위 감시. 정해둔 사용 시간(분)에 도달하면 확장 프로그램을 깨움 |
| ManagedSettings | 고른 앱에 차단 화면 씌우기 / 풀기 |
| ManagedSettingsUI | 차단 화면 꾸미기(펭곰이 그림, 문구, 버튼), 버튼 처리 |
| UserNotifications | 중간 한마디 알림 |
| App Groups | 앱과 확장 프로그램이 약속·기록을 함께 쓰는 저장소 |

**필요한 승인**: `com.apple.developer.family-controls` 권한. 개발 중에는 바로 쓸 수 있지만, **TestFlight·앱스토어 배포용은 애플에 신청해 승인받아야 한다** (무료, 며칠~몇 주). 앱과 확장 프로그램 번들마다 각각 신청.

## 3. 구성

```
pengom-ios/
  project.yml                 XcodeGen 설정 (Xcode 없이도 프로젝트를 글로 관리)
  App/                        본 앱: WKWebView + 브리지 + 앱 선택 창 + 권한 요청
  Shared/                     약속·개입 지점, App Group 저장소 (모든 타깃 공용)
  MonitorExtension/           DeviceActivityMonitor: 분 도달 시 기록 / 알림 / 차단
  ShieldConfigExtension/      차단 화면 모양 (펭곰이 녹은 얼굴, 문구, 버튼 이름)
  ShieldActionExtension/      차단 화면 버튼 처리 (나간다 / 그래도 본다)
  ReportExtension/  (2차)     오늘 정확한 사용 시간을 앱 안에 그려서 보여줌
```

## 4. 흐름

### 아침 약속
1. 웹 화면에서 예산을 분으로 적는다 (예: 30 → 딱 떨어지니 31분).
2. 브리지 `setPromise(31, "운동", th, overTh)` → App Group에 저장.
3. 오늘 00:00~23:59 `DeviceActivitySchedule`에 이벤트를 등록한다.
   - 진행 이벤트: 1분마다 (홈 화면 숫자 갱신용). 상한에 걸리면 2~3분 간격으로 넓힌다.
   - 중간 지점: 웹과 같은 불규칙 분 (예산의 41%, 72%, 예산 2분 전)
   - 예산 도달 이벤트
   - 초과 지점: 예산 +3, +7, +12, +18, +26, +35, +47분

### 보는 중 (앱은 꺼져 있어도 됨)
- 진행 이벤트 → MonitorExtension이 App Group에 `usedMinutes` 기록 → 앱을 열면 그대로 표시
- 중간 지점 → 알림: "13분째. 아직 약속 안이긴 해."
- 예산 도달 → 고른 앱에 **차단 화면** + 알림
- 초과 지점 → 알림: "나 지금 액체임."

### 차단 화면
- 그림: 녹은 펭곰이 얼굴 (`mascot_head_melt`)
- 제목: "네가 정한 거야."
- 부제: "내가 정한 거 아니고." + 이유를 적었으면 "“운동 하려고 아낀다.” 아침에 네가 쓴 말이야."
- 주 버튼 **나간다** → 앱 닫기
- 보조 버튼 **그래도 본다** → 차단을 풀고 15분짜리 유예 감시를 새로 시작, 15분 뒤 다시 차단. 기록에는 "약속 넘김"으로 남김

### 하루 정산
- `intervalDidEnd`(자정): 예산 이벤트가 울렸는지로 약속 판정, 어제 사용 분 저장, 차단 해제
- 앱을 열면 웹 화면의 `nextDay()`가 돌아 펭곰이가 크거나 녹는다

## 5. 웹 브리지 (안드로이드와 같은 이름)

| 메서드 | iOS 구현 |
|---|---|
| `getState()` | App Group에서 date, used(초 = usedMinutes×60), budget(분), history(초) |
| `isCounting()` | FamilyControls 권한 승인 && 고른 앱 1개 이상 |
| `openAccessibilitySettings()` | 권한 요청 → 승인되면 앱 선택 창 |
| `setPromise(...)` | 저장 + 오늘 감시 일정 다시 등록 |
| `openShorts()` | `instagram://`, `youtube://` URL로 열기 |

WKWebView는 동기 반환이 안 되므로 네이티브가 `window.__pengomNativeState`에 값을 밀어넣고 웹이 읽는 작은 어댑터를 둔다.

## 6. 한계

- **숫자 갱신은 이벤트 간격 단위**(1분, 상한에 걸리면 2~3분). 초 단위 실시간은 아님. 정확한 분은 2차의 ReportExtension으로 보여줄 수 있지만 그 값을 앱 로직으로 꺼낼 수는 없다(애플 정책).
- **영상 중간에 끼어들 수 있다**: 알림과 차단은 시간 기준.
- **다이내믹 아일랜드 실시간 갱신은 제외**: 서버 푸시가 필요.
- **확인 필요**: 한 일정의 이벤트 개수 상한, 이벤트가 늦게 울리는 경우. 브레인롯 사용자들도 차단이 풀리거나 다시 걸리는 문제를 겪고 있어 실기기 안정성 테스트가 필수.

## 7. 개발 환경과 비용

- **필수**: Apple Developer Program 연 $99 (TestFlight 포함). 결제는 사용자가 직접.
- **Mac**: Xcode는 macOS 전용. 없으면 GitHub Actions의 macOS 빌드 + XcodeGen + fastlane으로 TestFlight 자동 업로드 (App Store Connect API 키, 서명 인증서 필요). 이 경우 스크린타임 기능은 배포 권한 승인 후에야 작동.
- **스크린타임 API 사용료**: 없음.

## 8. 순서

| 단계 | 내용 | 확인 방법 |
|---|---|---|
| 0 | 개발자 계정, 번들 ID·App Group, Family Controls 배포 권한 신청 | 승인 메일 |
| 1 | XcodeGen 프로젝트 + WKWebView에 기존 화면 + 브리지 | 시뮬레이터 화면 |
| 2 | 권한 요청 + 앱 선택 + 하루 감시 + 중간 알림 | 실기기: 인스타 5분 → 알림 |
| 3 | 차단 화면 꾸미기 + 버튼 처리 + 유예 15분 | 실기기: 예산 도달 시 차단 |
| 4 | GitHub Actions → TestFlight 자동 업로드 | 내 아이폰 TestFlight 설치 |
| 5 | 리포트 확장, 홈 화면 위젯 | |
